🗂️ 实验十四 哈希表模拟数据存储

用除留余数法 + 线性探测模拟哈希表的插入与查找

📖 算法原理

哈希表（Hash Table）通过哈希函数把关键字直接映射到存储位置，理想情况下一次比较即可完成查找。本实验采用除留余数法：H(key) = key mod 11，表长 m = 11（m 通常取不大于表长的质数，可使关键字分布更均匀）。

不同的关键字可能映射到同一个地址，这种情况称为冲突。本实验用线性探测法处理冲突：从 H(key) 开始依次检查，若该槽已被占用，就继续探测 (H(key)+1) mod m、(H(key)+2) mod m …… 直到找到空槽。插入时把元素放入第一个空槽；查找时若遇到空槽或探测完整个表仍未找到，则说明元素不在表中。

装填因子 α = n / m（n 为已存元素个数，m 为表长）。α 越大，表中空槽越少，冲突概率越高，线性探测越容易形成"堆积"，平均查找长度（ASL）也就越长。开放定址法一般建议 α ≤ 0.75；查找成功时 ASL 等于所有元素查找比较次数之和除以元素个数，冲突越多查找性能越差。

时间复杂度：理想情况 O(1)，冲突严重时退化为 O(n)　空间复杂度：O(m)　平均查找长度：与 α 和冲突处理方式有关

💻 算法代码

/* 哈希表：除留余数法 + 线性探测法 */


#define M 11                  // 表长取质数


int HT[M];                   // 哈希表，-1 表示空槽


 


/* 哈希函数：除留余数法 */


int Hash(int key) {


  return key % M;            // H(key) = key mod 11


}


 


/* 插入：返回插入位置，-1 表示表满或元素已存在 */


int InsertHash(int HT[], int key) {


  int h = Hash(key), i = h, cnt = 0;


  while (HT[i] != -1 && cnt < M) {  // 该槽已被占用


    if (HT[i] == key) return -1;   // 已存在，不重复插入


    i = (i + 1) % M;               // 线性探测下一个槽


    cnt++;


  }


  if (cnt == M) return -1;         // 表已满


  HT[i] = key;                      // 填入空槽


  return i;


}


 


/* 查找：返回下标，-1 表示未找到 */


int SearchHash(int HT[], int key) {


  int h = Hash(key), i = h, cnt = 0;


  while (HT[i] != -1 && cnt < M) {


    if (HT[i] == key) return i;    // 比较成功


    i = (i + 1) % M;


    cnt++;


  }


  return -1;                      // 探测完整表仍未找到


}

📝 实验要点

  • 哈希函数应尽量均匀，表长 m 取质数可减少关键字聚集
  • 线性探测从 H(key) 开始顺序查找，插入时放入第一个空槽，查找时遇到空槽即可判定失败
  • 线性探测容易产生"堆积"：连续被占用的槽越多，后续插入和查找的探测次数越多
  • 装填因子 α = n / 11，α 越大冲突越多、平均查找长度越长；本实验可观察 α 与冲突次数的关系
  • 哈希表通常不存储重复元素，重复插入同一数值会被拒绝
  • 开放定址法删除元素时不能直接置空（会中断探测链），一般使用删除标记；本实验的「清空」直接重置整表并清零统计

🔧 冲突解决方案：线性探查法

不同的关键字可能算出相同的哈希地址，例如 12、23、34、45 都有 H(key) = 1，这就产生了冲突。本实验采用开放定址法中的线性探查法解决冲突：把哈希表看成一个环形数组，从 H(key) 开始顺序向后查找空槽，第 i 次探查的地址为

di = ( H(key) + i ) mod m　（i = 0, 1, 2, …, m-1）

  • 插入：d0 被占用就探查 d1，再被占用就探查 d2……直到找到空槽写入；探查 m 次仍无空槽说明表已满。
  • 查找：沿同一条探测序列逐槽比较，相等即查找成功；一旦遇到空槽立刻判定失败（空槽之后不可能再有该元素）。
  • 删除：不能直接把槽位置空，否则会截断探测链导致后面的元素找不到，通常打「删除标记」；本实验用「清空」重置整表。

以预置的 12、23、34、45 为例，四个关键字的哈希地址全是 1，线性探查依次把它们放到后面的空槽：

关键字H(key)=key mod 11探测过程冲突次数最终槽位
121槽 1 为空，直接存入01
231槽 1 被 12 占用 → 探查槽 2（空）12
341槽 1、2 被占用 → 探查槽 3（空）23
451槽 1、2、3 被占用 → 探查槽 4（空）34

线性探查的缺点是容易形成堆积（聚集）：一段连续的槽被占满后，后续落在这一段的元素都要反复探测，平均查找长度随之变长，因此开放定址法一般把装填因子 α 控制在 0.75 以下。页面的「探测序列」会把每次探查走过的槽位逐个显示出来，冲突槽标黄、命中槽标绿。
